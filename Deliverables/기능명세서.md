## 2. 기능 상세

### F-01. 환자 로그인
| 항목 | 내용 |
|---|---|
| 관련 화면 | C-01 |
| 트리거 | 환자 탭에서 "인증하고 시작하기" 클릭 |
| 처리 로직 | 실제로는 로그인 처리를 하지 않고 **P-02(병원 선택) 온보딩 플로우로 진입**시킨다. 환자는 아이디/비밀번호가 없고, 온보딩(F-04~F-07) 완료 시점에 최초 로그인 처리가 이루어진다. 재방문 환자는 F-05에서 조기 로그인 처리됨(4.4 참고) |
| 관련 함수 | `accounts.views.login_view` (환자 탭은 실질적으로 링크 이동만 수행, 별도 뷰 로직 없음) |
| 관련 테이블 | - |
| 예외 처리 | 해당 없음 |

### F-02. 병원 회원 로그인
| 항목 | 내용 |
|---|---|
| 관련 화면 | C-01 |
| 트리거 | 병원 탭 폼 제출 (`role=doctor`) |
| 처리 로직 | `django.contrib.auth.authenticate()`로 아이디/비밀번호 검증 → 성공 시 `login()` 세션 생성 → `doctors:home`으로 리다이렉트 |
| 관련 함수 | `accounts.views.login_view` |
| 관련 테이블 | `auth_user` |
| 예외 처리 | 인증 실패 시 "아이디 또는 비밀번호가 올바르지 않습니다." 재노출 |
| ⚠ 알려진 결함 | 로그인 성공 후 리다이렉트 대상 URL name(`doctors:home`)이 존재하지 않아 **NoReverseMatch로 500 에러 발생** — 로그인 기능이 현재 정상 동작하지 않음 (화면설계서 부록 이슈#5) |

### F-12. AI 상담 메시지 전송
| 항목 | 내용 |
|---|---|
| 관련 화면 | P-11 |
| 트리거 | 입력창에서 전송(POST, JSON body, Ajax) |
| 처리 로직 | 1) 요청 JSON에서 `user_input` 추출 2) 최초 메시지면 `build_initial_state()`로 초기 상태 구성, 아니면 기존 스레드에 이어 붙임 3) LangGraph `graph.invoke()` 호출로 AI 응답 생성 4) 마지막 메시지를 JSON(`{"reply": ...}`)으로 반환 → 프론트가 DOM에 즉시 추가 |
| 관련 함수 | `patients.views.chatbot_start` (POST 분기) |
| 관련 테이블 | `chat_session`(세션 식별용), 대화 내용 자체는 LangGraph 체크포인트에 저장 |
| 외부 연동 | LangGraph(`Chatbot.builder.build_graph`), LLM(내부적으로 `Chatbot.chat_node`가 처리) |
| 예외 처리 | 처리 중 예외 발생 시 HTTP 500 + `{"error": "모델 처리 중 오류가 발생했습니다: ..."}` |

### F-13. AI 상담 종료 및 요약 생성

## 4. 외부 연동 요약

| 연동 대상 | 용도 | 사용 위치 |
|---|---|---|
| Neo4j | 약물 상세정보(이름 등) 그래프 조회 | F-08, F-09, F-16 (`services.medical_graph.get_neo4j_drug_details`) |
| LangGraph | AI 상담 대화 그래프 실행 및 체크포인트(대화 이력) 저장 | F-11, F-12 (`Chatbot.builder`, 별도 SQLite 파일 `langgraph_checkpoint.db`) |
| OpenAI (`gpt-5.5`) | 상담 종료 시 요약(제목/본문) 생성 | F-13 (`services.end_summary`) |

> 본 문서 작성을 위한 로컬 렌더링 환경에서는 위 3개 외부 연동을 모두 목업(스텁) 처리했습니다. 따라서 캡처된 화면들의 "약 이름 정보 없음", 빈 AI 응답 등은 연동 자체의 실패가 아니라 **문서화 목적의 임시 비활성화 결과**입니다.
