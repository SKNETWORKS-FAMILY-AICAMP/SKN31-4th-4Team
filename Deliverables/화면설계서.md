# 화면설계서 (UI 명세서)

## 1. 버전 관리

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 정신과 약물 치료 지원 시스템 (복약메이트) |
| 버전 | v1.0 |
| 작성일 | 2026-08-07 |
| 작성자 | Claude (SKN31-4th-4Team 저장소 코드 기반 역산 작성) |

> 본 문서는 팀 저장소(`SKN31-4th-4Team`)에 이미 구현되어 있는 Django 템플릿·뷰 코드를 기준으로,
> `화면설계서_작성가이드.md`의 포맷에 맞춰 **역산(reverse) 작성**한 문서입니다. 와이어프레임은 목업 이미지가
> 아니라 실제 코드베이스를 로컬 렌더링(SQLite 임시 DB + 더미 시드 데이터)하여 캡처한 **실제 화면 스크린샷**입니다.
> 코드와 기획 의도가 다른 부분은 4.5(예외/에러) 또는 부록의 "발견된 이슈"에 별도로 표기했습니다.

## 2. 사이트맵 / IA (정보구조도)

```
로그인(C-01)
  ├─ [환자 탭] 인증하고 시작하기
  │     └─ 온보딩
  │         P-01 온보딩 시작
  │           └─ P-02 병원 선택
  │                └─ P-03 사용자 인증(전화번호+환자코드)
  │                     ├─ (건강정보 이미 있음) ──────────────► 로그인 처리 ─► P-08 메인
  │                     └─ (건강정보 없음)
  │                          └─ P-04 정보 조회중(로딩, 2초 후 자동 이동)
  │                               └─ P-05 본인 확인
  │                                    └─ P-06 건강정보 입력(기본: 키/몸무게/취침·기상/식사습관/흡연)
  │                                         └─ P-07 건강정보 입력(추가: 기저질환/임신여부) ─► 로그인 처리 ─► P-08 메인
  │
  └─ [병원 탭] 아이디/비밀번호 로그인 ─► (D-01 환자 목록으로 이동 예정 — 실제 코드는 미구현, 부록 참고)

P-08 메인 (환자 홈)
  ├─ 하단내비 홈 / 캘린더 / 기록 / 마이 (공통, 5.1 참고)
  ├─ 오늘의 복약체크 카드 → 각 항목 "복용했어요" (인라인 액션)
  ├─ 바로가기 카드
  │     ├─ 복약 캘린더 → P-09
  │     ├─ 병원 방문 기록 → P-13 (tab=visits)
  │     ├─ 처방받은 약 → P-13 (tab=prescriptions)
  │     └─ 상담 히스토리 → P-12
  └─ 하단 중앙 FAB "복약메이트에게 물어보기" → P-11

P-09 복약 캘린더
  ├─ 달력 셀 클릭 → ?date=YYYY-MM-DD 쿼리스트링으로 같은 화면 내 갱신 (P-10 별도 화면은 사실상 미연결, 부록 참고)
  └─ "복용했어요" 버튼 → 액션 후 캘린더로 리다이�렉트

P-11 AI 챗봇 ← P-08 FAB
  └─ 좌측 상단 "←"(대화 종료) → chatbot_end 액션 후 P-08

P-12 상담 히스토리
  └─ 카드 클릭 → P-15 상담 기록 상세

P-13 내 기록 (탭: 처방받은 약 / 병원 방문)

P-14 마이페이지
  └─ "로그아웃" 버튼 → C-01

──────────────────────────────────────────

D-01 환자 목록 (병원 회원)
  ├─ "+ 환자 등록" → D-02
  └─ 행 클릭 → D-03 환자 상세
       ├─ "+ 새 처방 등록" → D-04
       └─ 처방 행 클릭 → D-05 처방 상세
            ├─ "+ 약 추가" → D-06
            └─ 처방약 카드
                 ├─ "복약 체크" → D-07
                 ├─ "부작용 기록" → D-08
                 └─ "약 정보" → D-09

──────────────────────────────────────────

E-01 404 · E-02 500 · E-03 400 · E-04 403 · E-05 403(CSRF) — 전역 공통 에러 화면 (6번 참고)
```

#### 4.4 버튼 / 이벤트 정의
| 버튼/링크명 | 클릭 시 동작 | 비고 |
|---|---|---|
| 환자 탭 | 환자 진입 영역(인증하고 시작하기 버튼)만 노출, 병원 폼 숨김 | 클라이언트 사이드 전환만 수행 |
| 병원 탭 | 병원 로그인 폼만 노출 | 〃 |

| 상황 | 처리 방식 |
|---|---|
| 병원 로그인 아이디/비밀번호 불일치 | "아이디 또는 비밀번호가 올바르지 않습니다." 인라인 에러 카드, 같은 화면 재노출 |

## 5. 공통 컴포넌트 정의

### 5.1 하단 내비게이션 (Bottom Navigation) — 환자 앱

`patients/templatetags/patient_tags.py`의 `{% bottom_nav "탭이름" %}` inclusion tag로 렌더링되며, `patients/_bottom_nav.html`을 각 화면에서 재사용한다 (화면마다 복붙하지 않음).

| 탭 | 아이콘 | 이동 화면 | 노출 화면 |
|---|---|---|---|
| 홈 | 🏠 | P-08 메인 | P-08 ~ P-15 (챗봇 P-11 제외, 챗봇은 `{% bottom_nav "chat" %}`로 별도 activeTab만 씀) |
| 캘린더 | 📅 | P-09 복약 캘린더 | 〃 |
| 기록 | 📋 | P-13 내 기록 | 〃 |
| 마이 | 👤 | P-14 마이페이지 | 〃 |

> 가이드 예시의 "챗봇" 탭은 실제 구현에는 하단내비 항목으로 없고, P-08 메인 화면 중앙의 별도 FAB 버튼으로만 진입한다.

### 5.2 상단 헤더 — 병원(의사) 앱

`doctors/base.html`이 모든 D-01~D-09 화면에서 공통으로 extends 되며, 상단바(브랜드/의사명·병원명/로그아웃)와 `messages` 프레임워크 알림 영역을 제공한다.

| 요소 | 내용 |
|---|---|
| 브랜드 | "💊 복약메이트 · 병원 회원" |
| 사용자 정보 | "{{ doctor.name }} 선생님 · {{ doctor.hospital.hospital_name }}" |
| 로그아웃 | `accounts:logout`으로 이동 |
| 알림 영역 | `{% if messages %}` 블록, `django.contrib.messages`로 전달된 에러 문구를 상단에 표시 |

### 5.3 서브페이지 헤더 — 환자 앱

로그인 이후 대부분의 환자 화면(P-09, P-11~P-15)이 공유하는 상단 패턴.

| 요소 | 내용 |
|---|---|
| 뒤로가기 | 좌측 "←", 대부분 `main_url`(P-08) 또는 목록 화면으로 연결 |
| 타이틀 | `<h1>`로 화면명 표시 |

### 5.4 카드형 리스트 아이템 (record-card)

P-12, P-13, P-15, D-01, D-03, D-05 등에서 공통으로 쓰이는 카드 패턴 — 타이틀 1줄 + 메타정보(회색, 작은 글씨) 1~2줄 구성.

### 5.5 공통 버튼/모달 규칙 (가이드 대비)

가이드가 표준으로 제시하는 "저장/취소/이전·다음" 공통 버튼 세트나 "삭제·로그아웃 전 확인 모달"은 **현재 코드베이스에는 구현되어 있지 않다.**
- 저장 버튼: 화면마다 문구는 "저장하기"(P-14)/"등록하기"(D-02)/"저장"(D-07,D-08)/"추가하기"(D-06) 등으로 제각각이며 공통 컴포넌트로 추출되어 있지 않음.
- 로그아웃(P-14, D-01~D-09 상단): 확인 모달 없이 즉시 처리됨(부록 이슈#8).
- 토스트: `django.contrib.messages`가 병원 앱에는 연결돼 있으나(5.2), 환자 앱 화면들에는 연결된 토스트 UI가 없음 — 저장 성공/실패를 알리는 별도 시각적 피드백이 없고 페이지 재렌더로만 결과를 알 수 있음(부록 이슈#14).

> 신규 화면을 추가할 때는 이 문서의 5.5 항목을 참고해, 버튼 문구·토스트·확인 모달을 프로젝트 공통 규칙으로 새로 정의하고 기존 화면에도 소급 적용하는 것을 권장합니다.

모두 동일한 카드형 디자인(아이콘+타이틀+설명+"홈으로 가기" 버튼)을 공유하는 독립 템플릿으로, `doctors` 앱에는 대응 템플릿이 없어 병원 화면에서 오류가 나면 Django 기본 에러 처리(디버그 모드에서는 트레이스백, 운영 모드에서는 빈 화면)로 노출된다는 점을 참고 바랍니다.

**주의:** 5개 커스텀 에러 템플릿은 `patients` 앱에 이미 구현되어 있지만, 실제로 이 템플릿들이 쓰이려면 `DEBUG=False` + 프로젝트 루트에 `handler404`/`handler500` 등록(또는 Django 기본 규칙에 따라 `patients` 앱이 아닌 프로젝트 루트에 템플릿 배치)이 필요합니다. 현재 `config/urls.py`에는 handler가 별도 등록되어 있지 않아, 실제 배포(DEBUG=False) 시 이 템플릿들이 의도대로 연결되는지 QA 확인이 필요합니다.

## 부록. 코드 분석 중 발견된 이슈 목록

화면설계서 작성을 위해 로컬 렌더링을 진행하는 과정에서 발견한 실제 버그/미완성 지점입니다. 화면설계서 자체의 오류가 아니라 **현재 구현 코드의 결함**이므로, 다음 스프린트 버그 픽스 대상으로 옮겨 담는 것을 권장합니다.
